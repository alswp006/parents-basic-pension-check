# Architecture Review
Generated: 2026-09-30T15:33:13.176Z
Score: 62/100

## Summary
The domain layer (policy, calculator, pension, schedule, sanitize) is small, cohesive, and well-tested, and the SDK wrappers consistently guard against WebView-outside failures. The main problems are structural. A stale auto-generated `contract.ts` contradicts the real types, there is a large amount of unused scaffold UI code, and generic UI, domain code and SDK adapters are mixed in the same folders. Defensive try/catch and haptic logic is copy-pasted across many files. Pages (Home 313 lines, Result 274 lines) carry orchestration and validation logic that belongs in the lib layer.

## Issues
### Critical
- [duplication] `src/lib/contract.ts` declares a second, incompatible set of domain types and function signatures with the same names as `types.ts`. Region is Korean labels instead of 'metro'|'city'|'rural'. Verdict is a Korean sentence instead of 'likely'|'borderline'|'unlikely'. AppInput has businessIncome/rentalIncome instead of spouseEligible/luxuryAssets. PensionResult, ScheduleResult, FormState and RouteState all differ. Function types such as `calcScheduleFn(string, string)` and `judgeFn` also don't match the real `calcSchedule(string, Date)` or `judge(number, number)`. Nothing appears to import it, and it misleads anyone who treats it as the source of truth. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/schedule.ts, src/lib/calculator.ts / Fix: Delete `contract.ts`. If a contract file is needed, generate it from `types.ts` or re-export types from it. Keep `types.ts` as the single source of truth.
