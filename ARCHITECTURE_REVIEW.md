# Architecture Review
Generated: 2026-09-29T16:32:07.489Z

## Summary
The codebase is a small Toss mini-app (basic pension eligibility calculator) with a clean lib/components/pages split and well-documented, defensive SDK wrappers. However, a stale auto-generated `contract.ts` conflicts with the real `types.ts`, `validation.ts` acts as an overloaded hub module, and there are a few duplicated patterns (haptics try/catch, Amount/CountUp, NaN-guarding) plus unused pre-built components. Pattern consistency is otherwise decent, but import style and defensive-wrapper approaches vary.

## Issues
### Critical
- [consistency] src/lib/contract.ts declares a second, incompatible domain model that contradicts src/lib/types.ts. Region is Korean-region literals ('서울'|'경기'...) vs 'metro'|'city'|'rural'; Verdict is Korean sentences vs 'likely'|'borderline'|'unlikely'; Reduction is an object vs a string union; AppInput/FormState/PensionResult/ScheduleResult/IncomeBreakdown/PropertyBreakdown/AppResult have different fields; function signatures (calcScheduleFn takes a string `today`, getThresholdFn takes breakdowns, calcPensionFn takes a schedule) don't match the actual implementations (calcSchedule takes a Date, getThreshold takes hasSpouse, calcPension takes recognizedIncome/threshold). It is a stale generated artifact that misleads any developer or agent who trusts it, and nothing imports it. — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/calculator.ts, src/lib/pension.ts, src/lib/schedule.ts / Fix: Delete contract.ts or regenerate it from types.ts (e.g. `export type * from './types'`) so there is a single source of truth for domain types. Also stop the generator from emitting a contract that diverges from the implementation.
